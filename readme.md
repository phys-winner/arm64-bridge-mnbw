# arm64-bridge-mnbw

ARM32-to-ARM64 Android compatibility bridge and touch controls for Mount & Blade: Warband.

This repository contains the bridge, Android control code, guest-side payload
sources, and tests. It does not include the original game, its libraries, assets,
OBB files, decompiled application, or a playable APK. Game integration requires
your own copy of the supported Android release.

## What it does

- Runs ARMv7 guest code inside an ARM64 Android process using Dynarmic.
- Loads ELF32 guest libraries and forwards supported Android, JNI, libc,
  graphics, audio, and network calls to the host.
- Provides touch controls for battles, the world map, inventory, menus, and
  text input, alongside physical keyboard and controller handling.
- Includes storage migration, module selection, texture conversion, renderer
  compatibility fixes, and native settings payloads used by the port.
- Builds the bridge for `arm64-v8a` with 16 KiB ELF load-segment alignment.

The game-specific addresses and layouts target the Android **1.071** release.
Other versions need their own compatibility work. The standalone library does
not replace the original game or supply the APK integration layer.

## Source layout

| Path | Contents |
| --- | --- |
| `arm64_bridge/src/` | ELF loader, JIT host, host API thunks, JNI bridge, input and rendering logic |
| `arm64_bridge/tests/` | Source-only native regression tests and synthetic fixtures |
| `arm64_bridge/patches/` | Local ARM64 fixes against the pinned Dynarmic revision |
| `arm64_bridge/third_party/` | Required Boost headers, astcenc, and Texture2DDecoder sources |
| `work/controls/java/` | Java controls, launcher/storage helpers, build scripts, and JVM tests |
| `work/controls/` | Guest touch payload and control checks |
| `work/controls/guest_settings_tab/` | Guest settings payload, bridge protocol, and validation |
| `work/render_targets/` | Guest rendering payload sources and validation |

## Build the ARM64 bridge on Windows

Install Git, PowerShell, and these Android SDK components:

- Android NDK `27.2.12479018`;
- CMake `3.22.1`, including Ninja.

Run from the repository root in PowerShell:

```powershell
$env:ANDROID_SDK_ROOT = Join-Path $env:LOCALAPPDATA 'Android\Sdk'
.\arm64_bridge\build_arm64.ps1 -AllowNetwork -BridgeTarget MBExpMobile -NoLogs
```

The first build fetches Dynarmic at
`e77b1ba0b7da7cbe93021b01a663acfe7c4dd516`, initializes its upstream
dependencies, and applies `arm64_bridge/patches/dynarmic-arm64.patch`.
The output is `arm64_bridge/dist/libMBExpMobile.so`. The default minimum
Android platform is API 24. Building the native input tests does not run them
on an Android device.

For offline builds, pass `-DynarmicSourceDirectory` pointing to that revision
with its submodules initialized and the supplied patch already applied.
A populated `arm64_bridge/third_party/dynarmic/` is also used as an offline
override. Overrides are consumed as-is; CMake does not patch them again.

## Build the controls

The shell scripts currently target **Git Bash on Windows**. Set `JAVA_HOME`
to a JDK and `ANDROID_NDK_ROOT` to the NDK directory. For Java compilation,
also set `ANDROID_SDK_ROOT`, install Android platform 36 and Build Tools
`36.1.0`, and set `BAKSMALI_JAR` to an executable baksmali JAR.

```bash
bash work/controls/java/build_java_controls.sh
bash work/controls/build_guest_controls.sh
```

Java outputs (classes, DEX, and smali) go to `work/controls/java/build/`.
The guest touch payload goes to `work/controls/build/`.

The settings and rendering payload builders can validate their generated code
without the original game:

```powershell
.\work\controls\guest_settings_tab\build_payload.ps1 -SkipGuestChecks
.\work\render_targets\build_payload.ps1
```

Their Python validators require `pyelftools`, `capstone`, and `unicorn`.
Checks that explicitly read a guest library require a local original copy;
that copy is excluded from Git.

## Run source-only tests

For the native host tests, use a C++20 compiler, CMake 3.22 or newer, and Ninja.
Ensure CMake and Ninja are on `PATH`. On Windows, run these commands from a
Visual Studio developer shell:

```powershell
cmake -S arm64_bridge/tests -B .build/tests -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build .build/tests --parallel
ctest --test-dir .build/tests --output-on-failure
python -m unittest discover -s arm64_bridge/tests -p test_check_symbols.py
```

Pure Java control tests require a JDK and Git Bash, without an Android device:

```bash
bash work/controls/java/test_pure_java_controls.sh
```

Compiled Android IME checks use the classes generated by the Java build:

```powershell
python work/controls/test_popup_ime_wiring.py
python work/controls/test_text_preime_wiring.py
```

Tests containing extracted original-game machine code are deliberately excluded
from publication. Build directories, local QA evidence, device backups, signing
material, and game data are also excluded by the root `.gitignore`.
